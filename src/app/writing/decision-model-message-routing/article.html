Routing Agent Messages with a Local Decision Model

My agent waited about 15 s for an 8B LLM to classify every message. I tested local decision models for the job. The best fit, d3-lite, does it in half a second on the CPU, just as accurately.

Oney ErgeOctober 29, 20263 min read

I built YBM, an agent that runs on my laptop and does things on my computer when I message it on Telegram. Before it acts, it has to classify each message: is it chat, a question about its own progress, or a task, and which of its tools does the task need? There are 15 such routes.

An 8B LLM made that call, and it was slow: about 15 s per message before YBM could even start the work, on a GPU it shares with the model doing that work.

Why a decision model

A decision model is built for this kind of question. It reads a text and a list of options and returns a probability for each option in one pass, without writing any text, so it is fast [1].

I wanted one that runs on my own machine rather than in the cloud, so I served each candidate with LocalDeploy, my local model server, through llama.cpp [2]. I tested 11 open models, from 0.14B to 4.5B parameters, against the LLM YBM was using. I am sharing the results in case they help someone with the same problem.

The test

Each test is one message and one question. For example:

Message
"remind me tomorrow at 9am to send the budget draft"
Question
Which route should handle this message? 15 options, each with a one-line description, such as "chat", "files and folders", "open a site, web search" and "reminders and recurring jobs".
d3-lite's answer
"reminders and recurring jobs", 98% sure, in 0.6 s

I wrote 98 messages like this, covering all 15 routes, and counted how many each model routed correctly. Everything ran on one laptop: a Ryzen 9 5900HS with 8 CPU threads in use, and an RTX 3080 Laptop GPU with 8 GB. The models were quantized to 4 or 8 bits per weight (Q4_K_M or Q8_0), which makes them smaller and faster.

The point

d3-lite from vLLM Semantic Router routes a message in half a second on the CPU, as accurately as the 8B LLM, and leaves the GPU to the LLM. YBM now asks it first and passes a message to the LLM only when d3-lite is less than 90% sure. In my tests that handled about half the messages without the LLM and lost no accuracy. With a spare GPU, d3-mini is the most accurate at 0.17 s.
