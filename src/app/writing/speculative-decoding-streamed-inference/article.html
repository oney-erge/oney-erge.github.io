Speculative decoding on small GPUs · Part 1

Speculative decoding for streamed language model inference

In my previous series, Qwen3-14B ran on my 8 GB laptop GPU by loading its weights one part at a time, but every generated token cost one full pass through the model. Speculative decoding lets one pass produce several tokens without changing the output. This part explains how it works and measures it on the same laptop.

Oney ErgeOctober 14, 20268 min read

LLMs generate text one token at a time. Each new token depends on the tokens before it, so the model has to finish one token before it can start the next (Part 2 of the previous series).

On a GPU that holds the whole model, one pass takes a fraction of a second. When the weights do not fit, each pass reads most of the model from storage again. On my laptop, one pass of Qwen3-14B therefore takes seconds, and most of that time goes to moving weights, not to computing (Part 3).

The arithmetic for a few extra tokens is small next to that cost. Prompt prefill already shows this: one pass processes every token of the input prompt together. If the next few tokens of the answer were known in advance, one pass could check all of them.

Speculative decoding makes that guess with a much smaller model and lets the large model check it [1]. The idea of predicting several tokens and keeping the ones the model confirms goes back to blockwise parallel decoding [2].

Drafting and checking tokens

Speculative decoding uses two models that share a tokenizer. The target model is the large model whose output I want, here Qwen3-14B. The draft model is a much smaller model that guesses ahead, here Qwen3-0.6B from the same family [4]. It needs about 1.3 GB of GPU memory and stays on the GPU for the whole run.

One round, with the number of draft tokens fixed at k, works as follows:

  1. Step 1The draft model proposes k tokens, one after another. It is small and already on the GPU, so each guess is quick.
  2. Step 2The target model processes the text so far plus all k draft tokens in one pass. At every position it computes its own choice for the next token, exactly as it would without a draft.
  3. Step 3Starting from the first draft token, each draft token is accepted while it matches the target model's choice.
  4. Step 4At the first mismatch, the target model's own token replaces the draft token, and the rest of the draft is discarded. If all k draft tokens match, the target model's choice after the last one is added as a bonus token.
  5. Step 5The kept tokens join the answer, and the next round starts from there.

Each pass of the target model therefore produces between 1 and k + 1 tokens. It never produces fewer than one, because the target model's own token at the end of the round is always kept.

The same output as the large model alone

With the greedy decoding used in this series, every kept token is the target model's own top choice, given the same earlier tokens. The answer is therefore the one the target model would have written by itself. The draft model changes how many passes are needed, not which tokens come out.

With sampling, a draft token cannot simply be compared with one choice. Speculative sampling accepts each draft token with a probability set by the scores of both models and, after a rejection, samples a replacement from a corrected distribution. Leviathan et al. and Chen et al. showed that the result follows the target model's own distribution exactly [1].

In practice, checking several tokens in one pass can change the order of some floating-point additions, which can tip a near tie. Matching output tokens are therefore a measured result, and I report them below.

Tokens per pass and time per token

How many tokens one pass produces depends on how often the draft is right. If the target model accepts each draft token with the same probability, independently of the others, the expected number of tokens per pass is [1]:

E=1−αk+11−α (1)

where α is the acceptance rate, the fraction of draft tokens that the target model accepts, and k is the number of draft tokens per round.

Longer drafts pay off only when the draft is usually right. At an acceptance rate of 0.5, drafting 8 tokens instead of 4 adds almost nothing; at 0.9, it adds 2 tokens per pass.

The time per generated token follows from the cost of one pass and the cost of drafting:

ttoken≈tpass+ktdraftE (2)

where tpass is the time of one pass of the target model with the draft tokens included, and tdraft is the time the draft model needs for one token.

In streamed inference, tpass is seconds and tdraft is tens of milliseconds [5]. Drafting is almost free, so the time per token falls nearly in proportion to E. On a GPU that holds the whole model, a pass is fast, and drafting and checking take a larger share of it; there, the original papers report about 2 to 3 times faster generation [1].

SpecExec was designed for the streamed case. For models offloaded to RAM, it checks large trees of draft tokens in one pass and reports up to 20 accepted tokens per pass [3]. Part 2 returns to trees.

Fixed speculation measured on my laptop

Afterimage [5], the engine from the previous series, has a speculative mode that I call fixed speculation: the draft model always proposes k = 8 tokens per round. I measured it with the same 4 prompts as Parts 2 and 3 of the previous series, 4 generated tokens per prompt, greedy decoding, and the page cache cleared before each run.

Because the draft model stays on the GPU, the target model's own budget was set to 2.7 GB. The measured PyTorch peak for the whole run was 3.8 GB.

Two prompts finished in a single pass, because the draft model guessed every token that was needed. The code prompt needed 3 passes, because the draft model disagreed with the target model more often.

Averaged over the four prompts, fixed speculation took 9.2 s per generated token at a 3.8 GB peak. Without speculation, Afterimage's 4 GB plan from Part 3 took 17 s per token at 3.9 GB. Every prompt produced the same output tokens as the run without speculation.

Longer answers spread the prompt prefill over more tokens. In a later run with 8 generated tokens per prompt, fixed speculation averaged about 4.6 s per token [5].

The cost of the draft model

The draft model keeps about 1.3 GB of GPU memory for the whole run. The target model can no longer use that memory for its own weights, so each of its passes is slower than in the 4 GB plan without speculation.

The draft model also sets a floor. Together with the target model's own minimum, speculation needs about 3 GB, so it cannot run at the 1.6 GB that AirLLM needed in Part 2 of the previous series [5].

The gain depends on the prompt, as Table 3 shows, and these answers are short. Each round also drafts 8 tokens whether the draft is going well or not.

Conclusions

Speculative decoding was explained with a simple example, its expected tokens per pass were calculated, and fixed speculation was measured on Qwen3-14B streamed through my 8 GB laptop GPU. The following were concluded:

  1. A small draft model proposes several tokens, and the large model checks all of them in one pass. Every kept token is the large model's own choice, so with greedy decoding the output is the large model's own output.
  2. Each pass produces between 1 and k + 1 tokens. The expected number grows with the acceptance rate, and long drafts pay off only when the draft is usually right.
  3. In streamed inference, one pass takes seconds while one draft token takes tens of milliseconds, so almost every accepted draft token is time saved.
  4. On my laptop, fixed speculation with 8-token drafts took 9.2 s per generated token at a 3.8 GB peak, against 17 s at 3.9 GB without speculation, with the same output tokens.

Therefore, at about 4 GB of GPU memory, giving 1.3 GB of it to a draft model saved more time in these measurements than keeping more of the large model's weights on the GPU.

The draft in this part always came from a separate model and always had 8 tokens. Part 2 looks at the main variants: where else the draft can come from, how many tokens to draft, and whether to check one guess or a tree of guesses.
